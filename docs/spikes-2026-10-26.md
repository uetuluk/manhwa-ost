gcc 15.2 host compiler, clang 21 for HIP, `-DENGINE_ENABLE_HIP=ON`.

| Run | Audio | Wall | RTF | VRAM peak |
| --- | ---: | ---: | ---: | ---: |
| cot=off, 1250 semantic tokens | 50.0 s | 24.9 s | **0.50** | 6714 MiB |

VRAM peak includes ComfyUI's ~1.7 GiB tenant. YuE2 itself sits near 5 GiB, so

**Consequence:** generation is ~2× faster than listening. A 45 s cue costs
~20–30 s, so a 6-section chapter is a 3-minute job, not an hour.

## Y2 — ABC conditioning binds the score

One ABC file (`spike/abc/theme.abc`, D minor, 92 bpm, 16 bars, motif A + A′ + B),
rendered three times with deliberately incompatible style prompts
(`cot=melody`, seed 1234, same ABC):

| Run | Style | Key | Tempo | Chroma |
| --- | --- | --- | ---: | --- |
| A | cinematic orchestral, taiko | **D minor** (0.82) | 107.7 | — |
| B | music box, celesta, fragile | **D minor** (0.84) | 89.1 | 0.980 vs A |
| C | industrial, distorted brass | **D minor** (0.74) | 92.3 | 0.963 vs A |
| control | orchestral, **no ABC**, cot=off | F minor (0.84) | 117.5 | 0.65 vs A |

The three styled renders agree far more with each other than with the no-ABC
control. The prompt changes the arrangement; the ABC changes the music.

**Tempo is not reliable** (89–108 bpm for a 92 bpm score). Downstream cues must
be tempo-locked or their crossfades will smear. This is a post-processing
requirement, not an optional nicety.

## Y4 — cue continuity via semantic prefix

A (orchestral) → export semantic stream (1250 frames) → take last 50 frames
(2 s) → render B (synthwave) with `semantic_prefix_file` + same ABC.

Verified by re-exporting B's semantic stream:

```
prefix len 50, B len 1250
first 50 identical: True    overlap: 50/50
```

So a section's cue can be *spliced onto the previous cue's ending* — the next
cue starts in the exact musical state where the last one stopped. This is the
transition mechanism for cross-section changes.

## B1 — pages to cue sheet

14 MangaDex pages (SSS-Class Suicide Hunter ch.154, downscaled to 760 px) handed
to `opencode-go/deepseek-v4.1-flash` in one `opencode run --file ...×14` call.

| Run | Wall | Sections | Schema | Contiguity |
| --- | ---: | ---: | --- | --- |
| 1 | 64 s | 7 | ok | ok |
| 2 | 92 s | 7 | ok | ok |
| 3 | 52 s | 7 | ok | ok |

Boundaries at pages **6, 8, 9, 11** were identical in all three runs; 4 and 13
appeared in two of three. The model read the chapter correctly (Golden
Sovereign's ultimatum → oath flashback → six sovereigns refuse → resolve →
Divine Messages → White Lion → goblins rise) and reused motifs sensibly.

Output matches `contracts/chapter-score.schema.json`; `tools/validate-score.py`
checks schema + page coverage.

**Consequence:** analysis is cheap and stable enough to cache per chapter, with
a manual "re-read this chapter" action for the 1-in-3 boundary disagreements.
